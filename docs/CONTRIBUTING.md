# Contributing to DevTrail

Thanks for your interest in helping improve DevTrail! This guide explains how to contribute effectively.

## How to Contribute

1. Fork the repository.
2. Create a feature branch:

```bash
git checkout -b feature/your-feature-name
```

3. Make your changes.
4. Commit with clear messages.
5. Push to your fork and open a pull request.

## Branch Naming

- `feature/<name>` for new features
- `fix/<name>` for bug fixes
- `docs/<name>` for documentation updates

## Coding Style

- Use consistent indentation.
- Keep components and files organized.
- Write descriptive commit messages.
- Use existing naming conventions in frontend and backend.

## Project Structure

- `backend/` - Express API, controllers, models, routes
- `frontend/` - Next.js app, components, services, pages

## Testing Changes

- Run backend server with `npm run dev` in `backend/`.
- Run frontend with `npm run dev` in `frontend/`.
- Verify UI behavior and API functionality after your changes.

## Reporting Issues

If you find a bug or want to suggest an enhancement:

- Open an issue with a clear description.
- Include steps to reproduce the bug.
- Add screenshots if relevant.

## Code Review

- Keep PRs focused and small.
- Explain your changes in the PR description.
- Link related issues when available.

## Thank You

Your contributions help make DevTrail better for every developer.
